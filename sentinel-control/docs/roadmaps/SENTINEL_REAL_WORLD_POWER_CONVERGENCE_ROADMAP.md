## Selected Convergence Order

### Wave 1 - Coding/Workspace And Browser Live Power

Canonical title:

```text
REAL_WORLD_POWER_CONVERGENCE_WAVE_1_CODING_WORKSPACE_AND_BROWSER_LIVE_POWER
```

Why first:

- Sentinel already has real bounded workspace, shell, harness, and browser
  paths;
- these surfaces can produce useful missions quickly;
- they create proof for recovery, memory, workers, daemon, and operator UX;
- no new actuator family is required.

Required proof:

```text
complete a representative repository inspect-edit-test-debug mission
recover from one induced coding failure
complete representative live browser tasks
prove session continuity and changed-state recovery
measure time, interventions, recovery, receipts, replay, and kill
```

Current status:

```text

```

### Wave 2 - Desktop Real Control And Monitoring

Convert the injected desktop foundation into one production-quality, explicit
opt-in local backend on a supported platform. Preserve app/window/region
allowlists, sensitive-region handling, kill/revocation, receipts, and replay.

### Wave 3 - Realtime Voice Backend

Connect a real local or explicit provider audio transport to the existing voice
runtime. Voice remains cockpit transport and never authority.

### Wave 4 - One Real Channel Connector

Promote one provider connector to production-quality inbound/outbound
operation with durable credentials, recipient scope, approval, idempotency,
rate limits, receipts, FinalGate, and replay.

### Wave 5 - Real OS Credential Backend

Bind the existing vault/lease contracts to an OS keychain or equivalent local
production backend. Do not expand account/payment authority.

### Wave 6 - OS Service/Tray And Lightweight App

Package the existing core/daemon behind a lightweight local operator product
with tray, compact, and full cockpit modes.

### Wave 7 - Cross-Domain Real-World Mission Gauntlet

Certify useful missions spanning coding, browser, desktop, voice, channel,
memory, workers, daemon, recovery, proof, and kill behavior.
