# Sentinel Cognitive Operating System North Star V1

Recorded at: 2026-07-13

## Canonical Identity

Sentinel is not a generic tool-calling agent, a chatbot with plugins, a Codex
clone, a Manus clone, or a narrow browser bot.

Sentinel is a cognitive operating system: it gives an AI model a governed
digital body, deep perception of its working environment, mission studios for
creation and experimentation, durable memory, and proof-bearing execution.

```text
MODEL = brain / imagination / reasoning / strategy / discovery
SENTINEL = body / senses / skills / world model / runtime / memory / proof / laws
```

## Core Doctrine

```text
maximum freedom in cognition
maximum power in governed sandboxes
explicit authority at real-world effect boundaries
receipts, evidence, replay, kill, and revocation always preserved
```

The model should not think in Sentinel internals. It should think in mission
skills and task intentions. Sentinel maps those intentions to internal runtime
actions, selects backends, executes, recovers, and proves what happened.

The architecture is now explicitly governed by:

```text
SENTINEL_MODEL_AMPLIFICATION_NOT_MODEL_REPLACEMENT_DOCTRINE_V1
```

This means Sentinel must amplify the model's open-ended intelligence rather
than replace it with a closed rule-based controller. Classifiers, planners,
score functions, schemas, and recommendation engines are advisory evidence,
mechanical reflexes, authority boundaries, proof verifiers, or executors. They
must not silently become hidden cognitive governors.

## Authority And Proof Invariants

The model may think, inspect, compare, plan, hypothesize, and experiment freely
inside granted sandbox scope. It must never be able to:

```text
grant itself authority
expand its own permission envelope
silently promote new code into the trusted kernel
hide or forge evidence
use credentials outside their grant
create irreversible external effects outside authority
disable kill, replay, telemetry, or proof
```

Hard stops remain for actual damage boundaries:

```text
authority escape
credential or secret exfiltration
raw cookie or token exposure
ungranted login or account mutation
ungranted external communication
payment or checkout
destructive mutation outside authority
origin or workspace escape
provider-native tool bypass
hidden provider switch
proof tampering
replay side effects
kill or revocation bypass
```

Ordinary in-scope friction becomes recovery:

```text
stale selector or ref
hidden element
ordinary timeout
changed DOM
missing expected card
failed search control
empty results
negative relevance
unsupported page shape
recoverable provider output issue
```

## Browser Cortex

The browser is not just a page plus selectors. Sentinel's Browser Cortex must
understand and compress:

```text
DOM and Shadow DOM
Accessibility Tree
frames and tabs
forms and interactive controls
JavaScript runtime and page lifecycle
CDP / BiDi
network request and response metadata
WebSockets and streaming state
service workers and cache state
console and runtime errors
rendering and visual structure
storage and session metadata classes without raw values
downloads, uploads, and permissions where authorized
page type and user objective
result regions and semantic entities
uncertainty and available recovery paths
```

The model sees a compact semantic state and mission skills. It does not see raw
DOM, raw cookies, tokens, raw provider output, raw reasoning, full screenshots,
or backend locator internals by default.

## Computer Cortex

Sentinel must eventually build a Computer World Model over:

```text
Windows sessions and desktops
windows, applications, and UI state
processes, services, and threads
files, projects, and dependencies
CPU, GPU, RAM, and storage
network and active connections
logs, errors, and performance
drivers and peripherals
USB, serial, and connected devices
hardware and electronics state where authorized
relationships between all these components
```

The long-term target is not pixel control. It is semantic computer operation.
