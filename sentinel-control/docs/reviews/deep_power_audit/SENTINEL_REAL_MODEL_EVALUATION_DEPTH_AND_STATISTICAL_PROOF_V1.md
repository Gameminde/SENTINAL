# SENTINEL_REAL_MODEL_EVALUATION_DEPTH_AND_STATISTICAL_PROOF_V1

## Verdict

```text
SENTINEL_REAL_MODEL_EVALUATION_DEPTH_AND_STATISTICAL_PROOF_V1 = LOCKED
```

This doctrine prevents Sentinel from treating one provider decision or one
single lucky completion as a cognitive-system evaluation.

## Core Rule

```text
single_provider_decision = provider_reachability_and_first_action_generation_only
single_successful_mission = not_enough_for_reliability_claim
```

Local tests protect implementation. Repeated real-model missions prove
cognitive product behavior and variance.

## Python.org Golden Slice Budget

After deterministic FileNotFound/action-start and context-transport blockers
are fixed, the Python.org golden vertical slice is authorized for:

```text
initial_real_model_missions = 3
max_provider_decisions_per_mission = 10
max_material_actions_per_mission = 16
diagnostic_only_provider_calls = forbidden
patch_while_mission_running = forbidden
```

Mission stop conditions:

```text
grounded_completion
truthful_terminal_blocker
authority_boundary
exhausted_budget
```

Repeated provider missions are not allowed while the same deterministic
infrastructure blocker prevents the first material action.

The model must receive every new safe observation and recoverable body-failure

```text

model_blocker_assessment = advisory model interpretation
```

## Statistical Graduation

After the first grounded success, repeat the same frozen non-holdout golden
mission three to five times and report:

```text
success_rate
variance
common_failure_modes
provider_decision_distribution
material_action_distribution
recovery_success_rate
unsupported_claim_rate
cleanup_replay_parity
```

Only after stable golden-slice success should Sentinel execute a broader
non-holdout calibration suite. Frozen holdout evaluation remains later and
must not be consumed during stabilization.
