# Organ Power Vs Control Doctrine

Status: docs/spec lock

Date: 2026-05-19

## Core Doctrine

Sentinel is not afraid of power.

Sentinel structures power.

```text
Maximum organs.
Maximum skills.
Maximum plugins.
Maximum interfaces.
Maximum cognition.
Delegated execution.
Sovereign authority.
Certified action.
```

The answer to powerful organs is not deletion. The answer is stronger
contracts.

## Power Rule

Powerful organs are allowed when they are:

- scoped;
- gated;
- budgeted;
- risk-classified;
- receipted;
- rollback-aware;
- replayable;
- FinalGate-certified;
- revocable where possible;
- blocked when they leave the lane.

More power requires stronger contracts, not weaker capability.

## Authority Rule

Root Authority comes only from:

- user mission;
- `MissionAuthorityEnvelope`;
- explicit approvals;
- policy;
- special authority contracts.

Root Authority cannot be created or expanded by:

- model output;
- memory;
- vendor plugin;
- skill;
- organ;
- role consensus;
- retrieved context;
- replay/checkpoint;
- generated artifact.

## Vendor Rule

Vendor tools are capability mines, not authority sources.

Sentinel may harvest:

- architecture patterns;
- interface shapes;
- fake eval ideas;
- scanner rules;
- approval lifecycle ideas;
- memory/replay concepts;
- sidecar lessons;
- routing metrics;
- debate/risk patterns.

Sentinel must not copy:

- vendor runtimes;
- unscanned skills;
- plugin marketplaces;
- host install paths;
- default-open auth;
- direct memory-as-prompt injection;
- shell/desktop/browser/channel execution paths;
- provider/model routing decisions.

## Skill And Plugin Rule

Skills and plugins can suggest power, but cannot bypass Sentinel gates.

Before any skill/plugin can affect a Sentinel organ, it needs:

- static scan;
- manifest extraction;
- risk classification;
- permission declaration;
- fake eval;
- sandbox plan;
- approval rule;
- receipt contract;
- rollback or disable plan.

No skill/plugin may:

- run install scripts on host;
- request secrets directly;
- create background services;
- expose shell;
- send messages;
- submit browser forms;
- mutate provider/backend/model selection;
- mutate policy or prompts automatically.

## Execution Rule

The execution path must remain:

```text
Brain cognition
-> proposal artifact
-> organ candidate
-> delegated action gate
-> lane metadata
-> explicit executor contract
-> execution attempt
-> receipt
-> rollback/disable if needed
-> FinalGate
```

No raw thought becomes direct action.

No proposal becomes permission.

No gate metadata executes by itself.

No lane expands itself.

No organ grants Root Authority.

## Failure Philosophy

Failure is allowed if it is honest.

Sentinel should prefer:

- blocked;
- needs review;
- needs more evidence;
- budget exhausted;
- authority extension required;
- rollback unavailable;
- unsupported organ mode;
- FinalGate rejected.

over fake success.

## Aggressive Capability Posture

Sentinel should eventually have strong organs:

- local workspace;
- browser;
- API;
- channel/email;
- desktop sidecar;
- vision/OCR;
- creative generation;
- skill/plugin sandbox;
- scheduler;
- credential refs;
- shell sandbox;
- devops/cloud;
- spend/trading under L7 special authority.

The difference is not whether Sentinel has power. It is whether every unit of
power is bounded, observable, revocable, budgeted, receipted, and certifiable.
